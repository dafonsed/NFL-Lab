EV Tools & API

One guide to the VisualOdds EV workbench, its 18 tools, the quote data contract, and the EV API connection.

Welcome to the VisualOdds EV workspace

The workbench brings price comparison, expected value, arbitrage, fantasy, and tracking into one local workspace. Every tool below opens directly to its matching screen.

Workspace workflow

Permanent design demo is enabled. All EV+ tools are populated with illustrative prices, props, tickets, history and alerts. Demo data remains across reloads, and live examples stay fresh. Edits use separate demo storage. API sync is paused until demo mode is turned off.

Start in Odds comparison. Press Sync API to load the configured EV server’s quotes, add prices manually, or import a version 1 workspace JSON file. Choose a sport and market, then move among tools without leaving the workspace.

Records are saved in this browser. Export a JSON copy to move them between browsers or machines. The calculation tools use the same saved records, so a price entered for comparison can also appear in Positive EV, arbitrage, low holds, and alert screens.

Quote data contract

Sportsbook quotes need a stable id, sport, event, market, type, line, side, book, American odds, live status, and an observation time ts. Exchange quotes can add exchange and liquidity. DFS props, prediction contracts, bets, results, and alerts have separate record arrays in the version 1 workspace format.

Positive EV requires a complete set of outcomes from another book at the same event, market, line, and live status. Live calculations exclude quotes older than 90 seconds. The detailed format is maintained in the project’s EV workbench data contract.

Markets

  • Odds comparison — compare entered prices and recorded movement.
  • Positive EV · pregame and Positive EV · live — compare offered odds with no-vig estimates from complete opposing books.
  • Arbitrage · pregame and Arbitrage · live — inspect opposing prices and calculated stake splits.
  • Middles — find spread and total pairs with an interval where both bets can win.
  • Low holds — compare the combined margin of opposing best prices.

Builders & research

  • Promo / bonus converter — balance a promotional side with a cash hedge.
  • Parlay builder — combine independent legs using saved fair probabilities.
  • Sharp money / Pro — inspect exchange liquidity, opposing prices, and movement history.

Fantasy tools

  • Fantasy lines — compare entered player lines and hit probabilities.
  • Fantasy optimizer — rank two-pick combinations against saved payout rules.
  • Fantasy slip builder — calculate hit-count distributions and projected payout.
  • Fantasy alerts — review newly entered props against local alert rules.

Records & alerts

  • Prediction traders — track contracts, order book snapshots, positions, and trades.
  • Bet tracker & CLV — grade saved bets and compare booked and closing prices.
  • Player prop trends — inspect entered results, hit rates, and paired-game relationships.
  • Movement & price alerts — manage thresholds and review local notifications.

EV API routes

VisualOdds connects to the EV Tool server over the local network on port 8000. Browser requests use the VisualOdds routes below. The VisualOdds server attaches the required X-API-Key header to every upstream request, including health and status. The key stays in server configuration.

  • GET /api/ev/health and GET /api/ev/status — local service health and quote counts.
  • GET /api/ev/quotes — normalized sportsbook quotes for the workbench.
  • POST /api/ev/quotes — upsert a JSON array of normalized quotes.
  • GET /api/ev/matches — events represented by those quotes.
  • DELETE /api/ev/matches/{id} — remove an event and its quotes.
  • POST /api/ev/scrape?url=… — reserved for future use.

Connect the EV API

Run the VisualOdds Node app on a computer connected to the same WiFi or network as the EV API host. Configure the connection in the project’s ignored .env.local file using these server-only settings. Environment variables override the file when supplied.

EV_TOOL_API_URL=http://<server-lan-ip>:8000/
EV_TOOL_API_KEY=<your-api-key>

Open the EV workspace and press Sync API when the server is available, or enable Auto-refresh every 15, 30 or 60 seconds. Auto-refresh starts off on every page load, pauses in background tabs and while editing, and backs off after temporary errors. Choose an interval your server supports. A successful sync replaces the previous API snapshot and example sportsbook quotes, preserves manual prices, and shares the result across comparison, EV, arbitrage, builders, and alerts. The hosted site cannot reach this LAN connection.

The quote feed panel shows the last successful sync separately from the latest price observation, flags expired live prices, and explains which data the selected tool uses. Saved prices remain available when a request fails. Authentication or invalid-data errors pause automatic retries until you fix the issue and press Sync API.

GET /quotes must return a complete current snapshot as a JSON array or an object with a quotes array. Each quote needs a stable ID, a bookmaker, and its real observation time with timezone, in addition to its sport, event, market, side, and odds. Invalid records, duplicate IDs or partial snapshots leave the previous snapshot intact. An empty successful array clears the previous API quotes. A soccer sport is displayed as Soccer, and a 1x2 market uses three outcomes.

For example, POST /api/ev/quotes accepts a JSON array like this:

[
  {
    "id": "feed:event:total:over:book",
    "sport": "NFL", "event": "Arizona vs Seattle",
    "market": "Game total", "type": "total", "line": 44.5,
    "side": "Over", "book": "Example Book", "odds": -110,
    "live": false, "ts": "2026-09-25T00:00:00Z"
  }
]

Manual and imported records remain available when the API is offline. The quote sync does not populate fantasy props, prediction contracts, or personal bet records; those still use their own workspace records. The bundled Python folder remains available as an optional development scaffold. The VisualOdds API overview describes the app’s separate public preview routes.

Data needed for all tools

The connection credentials are configured. To populate every tool, the API must supply the datasets below. Additional endpoint names and response formats need to be confirmed before their adapters can be connected.

  • Sportsbook and exchange quotes: complete opposing prices, stable cross-book event and selection IDs, periods, timestamps, live status, and exchange liquidity. The existing quote sync consumes these records.
  • DFS: platform/player lines, hit probabilities with their source, and actual payout tables and entry restrictions for each app.
  • Prediction markets: contracts, bids, asks, depth, settlement terms, and authorized personal positions and trades when account tracking is wanted.
  • Player history: historical game statistics, player IDs, matching game IDs, dates and correction status for trends and correlations.
  • History and closing odds: timestamped movements and the defined closing price for each book and selection. Local movement history starts when quotes are synced.
  • Event mapping and results: match IDs, schedules and statuses aligned with the tracker. The tracker already has a separate game-results connection; the quote feed needs matching IDs and closing prices.
  • Delivery details: sample responses or OpenAPI, supported coverage, snapshot/removal rules, allowed polling rate, rate limits and errors. Public hosting needs an API reachable from the hosted server.

Promo amounts and terms can be entered manually. Executable sportsbook parlay pricing, correlated same-game pricing and automatic account imports require additional provider support. Download the full API handoff for all 18 tools, field examples and proposed routes.
