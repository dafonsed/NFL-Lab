Audited locally on 2026-09-22 (America/Phoenix; evaluation files use 2026-09-23 UTC). Engine: `pregame-score-simulation-v2`. The RNG namespace remains v1 so unchanged clean inputs preserve their seeded score draws. This audit traced the actual source, adapters, formulas, samplers, UI and evaluator; it did not accept the earlier design document as evidence.

**Conclusion: 19 PASS, 2 FAIL, 2 NOT VERIFIED after fixes.** The implementation now meets the tested arithmetic and separation requirements. It remains an experimental score-distribution model, not a fully rule-faithful or validated betting model. Two modeling defects/limitations remain, and historical publication-time fidelity and untouched holdout separation cannot be established.

The working tree also contains active changes to standard models and site design from other work. This audit edited simulation-specific modules/tests/docs, its server wiring and its README paragraph. It did not edit standard or live prediction formulas, features or weights. Existing unrelated changes were preserved.

## Fixes made and their evidence

1. **Shared settings alias:** changing a returned `inputs.weights.min` to 100 changed a later simulation to `withheld`, because it referenced the existing live model's config. Copying the returned weights removes that write path. Regression test also checks that the live prior and frozen input objects remain unchanged.
2. **Market rounding:** a zero-line total comparison could exceed probability one through accumulated floating-point error. Bounds now apply to win/push and conditional masses, with synthetic exact push/spread tests and a reproduced real sampler case.
3. **MLB historical leakage:** cached schedule examples contained one final twice: original official date and later resumption. Previously both were normalized to the original date. The simulation adapter now assigns a conservative end-of-resumption-day availability to all copies; known late availability also blocks a duplicate with missing metadata.
4. **Basketball date matching:** an ESPN evening game may have a next-day UTC timestamp. The schedule's requested official day is now retained before lookup and prior construction, making the matchup selectable and enforcing the selected-day cutoff.
5. **Malformed inputs:** impossible calendar dates, numeric/non-string dates and invalid team identifiers no longer enter history or crash date filtering. Invalid availability metadata fails closed.
6. **Standard archive side effects:** opening simulation props previously called shared standard boards that capture prediction, paper and NFL line records. The simulation now runs those same forecast methods through separate instances with capture/line-history writes disabled. Only raw data provider caches are shared; no simulation result is sent into a standard model.
7. **Reporting:** added correlation/outlier/bound warnings, historical publication caveats, and clear separation between workload-based TD occurrence estimates and historical-outcome line probabilities. Invalid TD probabilities are withheld. The latter are already distinct estimates in the standard model; this audit did not change either formula.
8. **Evaluation provenance:** added code hashes, per-game input digests/seeds/counts and saved rows, missing-period checks, generated versioned UI evidence and an exact verification command. Removed claims of an independently untouched holdout that the code cannot prove.

## Complete flow in plain language

1. **Data received.** The app sends sport, official game day, matchup ID, run count and optional seed to `/api/simulation/run`. The store loads public schedule identity/status, season format, home/away teams and completed earlier team scores. NFL uses the nflverse schedule; NBA/WNBA fetch the selected teams' two-season regular/postseason schedules; MLB fetches a 449-day schedule window. Sources retain URLs, timestamps and hashes. No current player injuries, weather, lineups, betting odds or live scores enter this game engine. Player cards arrive separately through `/api/simulation/props`.

2. **Features and weights.** The simulation uses the existing live game model's score-history prior, not the standard player research rating. Earlier games within 450 days receive `2^(-ageDays/halfLife)` weight. A league score baseline is shrunk toward 40 games of the configured sport mean. Home advantage is shrunk with denominator `weightMass + 80` and bounded to 8% of the configured mean. Team offense and points/runs allowed are venue-adjusted and shrunk toward the league baseline. Their history fraction is `weightMass / (weightMass + shrink)`. Each team's mean before simulation is **half its offense + half its opponent's allowed scoring ± half home advantage**, bounded to 45–165% of the league mean. Confirmed neutral sites remove that last venue term. Weighted scoring variance affects basketball draws; NFL/MLB use their own scoring distributions instead of adding this variance a second time. See `lib/live-game-model.mjs:46`.

   | Sport | Initial score mean / SD | Team sample limit / minimum | Recency half-life | Shrinkage |
   |---|---:|---:|---:|---:|
   | NFL | 22 / 11 | 16 / 5 | 180 days | 6 equivalent games |
   | NBA | 112 / 13 | 30 / 8 | 90 days | 10 |
   | WNBA | 81 / 11 | 30 / 8 | 90 days | 10 |
   | MLB | 4.5 / 3.2 | 40 / 10 | 60 days | 15 |

3. **One game.** NFL draws a Poisson number of scoring events with mean `teamMean / 5.73`; events score 2/3/6/7/8 with probabilities .02/.30/.04/.57/.07. Ties receive the disclosed terminal OT approximation. NBA/WNBA draw independent normal team scores with the prior means/variances, round and floor at zero; ties add five-minute scoring draws until resolved. MLB draws clustered runs per out across half-innings, skips unnecessary home batting, stops approximate walk-offs and continues tied games. A .48 extra-run chance approximates the automatic runner in regular seasons from 2020 onward. Unsupported schedules and unresolved continuation caps withhold/error instead of inventing results. See `timedGame`, `baseballGame`, `footballPoints`, `inningRuns`.

4. **Randomness.** Event counts, event sizes, scoring deviations and continuation outcomes represent game-to-game outcome variation under fixed assumed strength. The PRNG is seeded through SHA-256. It does not draw new injuries, team quality, weather, correlated pace or alternative fitted weights. Independent team scoring can misrepresent totals and margins; increasing the run count does not fix that assumption.

5. **Repeating games.** Run the generator N times. Count home wins, away wins, ties and continuations. Sort scores, total scores and home-minus-away margins to derive empirical means, medians, discrete 10th/90th percentiles and full probability masses. Win probability is wins/N. Wilson 95% intervals measure finite-simulation sampling uncertainty only. At 10,000 runs the worst-case sampling margin is about one percentage point.

6. **User interpretation.** Expected score is an average, not a promised or necessarily integer scoreline. Middle 80% is a modeled scenario band, not guaranteed real-world coverage. Tie probability is part of the three-outcome win partition; overtime probability overlaps eventual wins/ties. A positive home margin favors home. Manual odds comparisons separate raw price-implied chance, proportional no-vig chance and model chance excluding pushes; the percentage-point gap is not expected profit. Prop cards use existing player forecasts and may disagree with team totals because they are not joint simulated outcomes. TD workload probability and historical TD mapping can also differ and are now labeled separately.

7. **Largest influences.** Structurally, the scoring centers are driven by recent scoring/allowed scoring and shrinkage; the 50/50 mix gives those terms equal direct coefficients, not equal empirical importance. Distribution width and fixed NFL event frequencies strongly affect win probabilities and tails. Sample recency/size determines how much the baseline dominates. Venue is bounded. Unmodeled current personnel and shared pace may materially change reality. No empirical feature-importance ranking or parameter-uncertainty study has been established; these statements follow from the formulas, not a fitted attribution analysis.

8. **Historical validation.** The evaluator reads the cached NFL schedule, builds a 284-game 2022 outcome-frequency baseline with one pseudocount per class, and replays 285 games in each of 2023, 2024 and 2025. Each game uses 2,000 runs, seed `evaluation:<game-id>`, and only earlier dates for its prior. The 2023 phase is a diagnostic calibration table, not calibration training; 2024 and 2025 are labeled validation/final periods with no fitting routine. No coefficients were tuned by this audit. An untouched prospective holdout is not established.

   |---|---:|---:|---:|
   | 2023 calibration diagnostic | 285 | .2361684 | .2458019 |
   | 2024 validation | 285 | .2328377 | .2479414 |
   | 2025 final diagnostic | 285 | .2320523 | .2496530 |

   All phase statistics match the before-fix replay exactly. For 2025: log loss .68099 versus .71674 baseline; total MAE 10.80, margin MAE 10.31, team-score MAE 7.64; total/margin middle-80% coverage 90.18%/87.37%. The home-Brier difference is -.01760 with approximate game-level interval [-.02453, -.01067]; this ignores team/week dependence. In the 60–70% bin, predicted home chance averaged 62.80%, while 40/45 games were home wins (88.89%). That is poor calibration and broad distributions despite beating a weak baseline. Log loss floors probabilities at 1e-6 for numerical scoring. No betting profitability, prospective accuracy or generalization to the other sports is established. NBA/WNBA/MLB do not have this engine's league-wide chronological outcome evaluation.

9. **Run/configure.** Start with `npm start`, open Models & Data → Simulation (or `/nfl/simulation`, `/nba/simulation`, `/wnba/simulation`, `/mlb/simulation`), select date/matchup, choose 1k/10k/25k/50k runs and optionally a seed, then Run simulation. The API also accepts any integer between 1k and 50k. Expand input/validation/source panels and download JSON. Enter paired American prices only when they refer to the same two-way full-game settlement. Use the props market/team/player controls for separate player forecasts. Historical choices are explicitly reconstructions.

## Rule checks and unresolved evidence

NBA/WNBA five-minute overtime matches [NBA Rule 5](https://official.nba.com/rule-no-5-scoring-and-timing/) and [WNBA 2026 Rule 5, printed page 17](https://cdn.wnba.com/sites/4/2026/05/2026-WNBA-Official-Rule-Book.pdf). Their possession/endgame dynamics are still approximated.

NFL's terminal +3/+6 winner and fixed conditional tie probability do not implement the possession opportunities and clock in [NFL Rule 16](https://operations.nfl.com/media/ntif5hxb/2025-nfl-rulebook-final.pdf). Era-specific historical overtime changes are also not modeled. Fixing this requires a separately tested drive/possession model and new evaluation, not an arbitrary adjustment fitted to the already-inspected 2025 data.

MLB's extra-inning runner applies to regular seasons; see [MLB automatic-runner rule](https://www.mlb.com/glossary/rules/designated-runner). Completion after the original date matters for [suspended games](https://www.mlb.com/glossary/rules/suspended-game). The current simulation needs regulation-only score/exposure and event-level batting/runner outcomes to remove extra-inning double counting and represent walk-off home-run margins correctly. A hardcoded correction or guessed home-run rate would not resolve the validation gap.

Missing evidence: immutable as-published schedules/results and historical lineups; reliable regulation-versus-overtime scoring/exposure for the whole evaluation; fitted/validated possession and run-advancement mechanisms; a locked future evaluation set; this engine's NBA/WNBA/MLB holdouts; prospective timestamped game forecasts and production load measurements. None is marked passed by inference from unit tests.
