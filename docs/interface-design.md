# Sports Lab interface

Sports Lab keeps its existing plain HTML/CSS/JavaScript architecture. `lib/site-layout.mjs` renders the common shell, and `public/app-design.css` is the final shared visual layer. Sport styles keep their data-specific layouts. `public/ui-icons.js` supplies one icon set on the server and client.

## Visual system

The base is black with distinct charcoal surfaces. Shared tokens in `public/app-design.css` define backgrounds, borders, text, controls, selection and actions. Blue and cyan identify actions and selected data; dark capsules identify secondary actions. Pale-blue selected history tabs are distinct from blue/coral above/below-line results. Amber identifies ties and warnings. Player headers use a faint cyan-to-black glow; analytical panels have quiet, untextured surfaces. Historical outcomes always retain labels; ratings and probabilities retain distinct names and scales. Legacy sport styles consume the same palette rather than retaining separate green or purple surfaces.

The home page opens into player research using existing sport/date/market APIs. `mountResearchWorkspace` in `public/player-research.js` gives NFL, MLB, NBA, WNBA, NHL and Soccer the same player-first structure: searchable player chooser, compact player header, market tabs, a large game-history chart, and adjacent matchup/line panels. The Board tab retains the comparable player rows supplied by `public/product-ui.js`. The home preview includes 30 actual players and links to the complete sport workspace. Dates, games, filters, saved players and other tools remain available; secondary controls sit in labeled disclosures. Selecting a player updates the URL and restores that selection on refresh. On phones it also brings the research region into view and moves keyboard focus there. Longer charts scroll within their own container and retain complete game logs.

System typography, tabular figures, consistent radii, explicit focus states, and readable tables apply throughout research, Trends, Live, Simulation, evidence archives, dialogs and the ticket editor. Capsule buttons, circular icon actions, rounded form fields and inset segmented controls use the shared interaction tokens. Clickable records retain their row layout; source links remain recognizable links. The inset sidebar uses restrained blue/cyan light and scrolls its navigation independently below the logo. Phones use a matching floating navigation bar with additional destinations available through More. Long tables and market strips scroll within their containers. Trends prioritizes the selected chart on mobile, with an explicit player chooser. Live separates game odds and player projections into keyboard-accessible tabs.

Player research and Trends share supporting-stat and model-estimate components. Supporting stats form a compact strip with the selected sample count; metric-specific sample counts appear when missing fields change the denominator. Projection, sportsbook line and model probability occupy aligned columns. Detailed calculation explanations remain in named disclosures. Historical chart context stays visible alongside an expandable source explanation. Matchup results and venue/weather share one context panel. No large probability banner or repeated sample paragraph is needed to communicate these distinctions.

## Product clarity

The public entry presents actual data first and links to existing tools. Relevant caveats remain visible near results, with details in the player view. Source failures, historical context, quote provenance and stale markers remain explicit. Model over probability is never renamed confidence; a projection difference is not expected value. NFL performance is labeled as an NFL archive. Paper returns are hypothetical, local tickets are browser-only, and simulations are experimental. More simulation runs are never described as evidence of accuracy.

Empty tables and unavailable chart histories have explicit explanations. Evidence dialogs have accessible names and sticky close-header bands. Model inputs, formulas, source receipts, sample sizes, warnings and raw data remain available through the existing details and Dev mode.

## Interaction conventions

Filter sheets edit drafts: Cancel/Escape discards them, Apply changes the existing page controls, and presets are scoped by sport/workspace. Hidden view-specific controls are omitted from the sheet. Appearance supports persisted compact spacing and reduced motion. Switching Research/Trends preserves compatible date/week/market selections.

Async controllers reject obsolete responses. Bounded requests distinguish failure from an empty dataset and provide retry actions. Refreshes retain valid content for the same selection; changing sport/date clears incompatible content. Simulation input edits invalidate previous results without changing the model. Ordinary typed fields in the ticket editor update without rebuilding and dropping keyboard focus. Existing storage keys and data semantics remain intact.
